# 商业化 IDC 云管系统（主控 + KVM 被控）项目全生命周期文档

## 1. 立项与规划阶段：回答「为什么要做」

### 1.1 项目背景与目标
本项目旨在自研一套商业化的 IDC 云管系统，采用“一对多”的主控（Web 控制端）与被控（KVM 母鸡节点）架构。系统的核心商业模式为**软件授权售卖**，通过分离“主控授权”与“母鸡配额授权”实现灵活的商业变现。

**核心目标**：
- 打造一款支持一键安装、即插即用的商业级 KVM 虚拟机管理面板。
- 实现高度自动化的资源交付（虚拟机开通、网络分配、系统安装）。
- 建立完善且防破解的商业授权验证体系（主控 License + 母鸡配额）。

### 1.2 商业价值与变现模式
- **主控授权费**：按月/年/永久售卖主控端软件的使用权。
- **母鸡配额费**：按台数阶梯定价售卖被控节点（母鸡）的接入配额。主控购买可包含基础配额（如默认 0 台或 2 台），超出部分需独立购买授权。
- **定制化服务**：为大型 IDC 客户提供 UI 定制、特殊网络架构适配等增值服务。

### 1.3 核心干系人与资源需求
- **产品/项目经理**：负责需求定义、商业模式设计与进度把控。
- **后端研发工程师（Go）**：负责主控端业务逻辑、授权系统及被控端 Agent 开发。
- **前端研发工程师（Vue/React）**：负责主控端 Web 面板与用户中心开发。
- **运维/测试工程师**：负责系统部署测试、环境兼容性测试及自动化安装脚本编写。

## 2. 需求与用户研究阶段：回答「到底做什么」

### 2.1 目标用户画像
- **中小型 IDC 服务商**：需要一套低成本、易维护的面板来售卖 VPS 产品。
- **企业私有云管理员**：需要集中管理内部多台物理服务器的虚拟化资源。
- **个人服务器玩家（One-Man IDC）**：追求极致性价比和一键部署的便捷性。

### 2.2 核心业务需求清单
- **授权管理系统（独立中心）**：
  - 颁发与验证主控 License。
  - 管理每个主控绑定的母鸡数量配额。
  - 授权到期自动降级或锁定功能。
- **主控端（Web 面板）**：
  - **用户模块**：注册、登录、实名认证、财务充值。
  - **产品模块**：套餐定义（CPU/内存/磁盘/带宽）、镜像管理。
  - **资源模块**：母鸡节点管理（添加、删除、监控）、IP 地址池管理。
  - **订单模块**：购买、续费、升级、退款流程。
  - **工单模块**：用户与管理员的沟通渠道。
- **被控端（KVM 母鸡 Agent）**：
  - **一键接入**：在母鸡执行一行命令（如 `curl -sSL install.sh | bash -s <Token>`），自动完成环境安装并注册至主控。
  - **虚拟机生命周期**：创建、开机、关机、重启、重装系统、销毁。
  - **资源隔离**：基于 KVM/QEMU 和 cgroups 实现 CPU、内存、磁盘 IO 限制。
  - **网络控制**：桥接网络配置、带宽限速（tc）、MAC 地址绑定防欺骗。
  - **状态采集**：实时上报母鸡和虚拟机的运行状态至主控。

## 3. 产品设计阶段：回答「用户怎么用」

### 3.1 角色与权限设计
- **全局管理员（超管）**：拥有最高权限，管理节点、套餐、用户、财务，配置系统参数及录入授权。
- **普通用户（租户）**：浏览产品、充值购买、管理名下虚拟机（开机/关机/VNC/重装）。

### 3.2 核心交互流程
- **授权激活流程**：
  管理员安装主控 -> 填入购买的 License Key -> 主控向中心授权服务器验证 -> 验证通过，解锁主控功能并获取母鸡配额。
- **母鸡接入流程**：
  管理员在主控后台生成节点接入命令 -> 登录母鸡 SSH 执行命令 -> 被控端自动安装并向主控发起注册 -> 主控校验配额 -> 配额充足，节点接入成功。
- **用户购买虚拟机流程**：
  用户选择套餐与系统镜像 -> 支付订单 -> 主控调度器选择可用母鸡 -> 发送创建指令至被控端 -> 被控端执行克隆镜像与网络配置 -> 虚拟机启动并交付给用户。

### 3.3 界面原型标准
- **管理后台**：注重数据可视化（资源使用率大盘）与操作效率（批量操作）。
- **用户前台**：注重购物体验（清晰的购物车）与控制台易用性（直观的 VNC 终端）。

## 4. 技术设计阶段：回答「技术怎么实现」

### 4.1 技术选型
- **中心授权服务器**：Go + MySQL + Redis。
- **主控端（Master）**：
  - 后端：Go 语言（高性能、高并发）。
  - 数据库：MySQL（业务数据） + Redis（缓存与任务队列）。
  - 前端：Vue 3 + TypeScript + Element-Plus/Arco Design。
- **被控端（Agent）**：
  - 语言：Go 语言（编译为无依赖二进制，直接在母鸡运行）。
  - 虚拟化层：KVM/QEMU + libvirt（通过 `libvirt-go` 库交互）。
  - 操作系统兼容：严格限定并适配主流 Linux 发行版（Ubuntu 20.04/22.04, Debian 11/12, CentOS 7/8/AlmaLinux）。

### 4.2 核心架构设计
- **一对多拓扑**：主控暴露 gRPC 或 HTTPS 接口，被控端启动后与主控建立长连接或定时轮询。
- **安全通信**：主控与被控之间通信必须采用 TLS 双向认证，防范中间人攻击和指令伪造。
- **防破解设计**：
  - 核心授权代码混淆/加壳。
  - 主控定时向中心授权服务器心跳打卡，断网超限则锁定。
  - 绑定主控所在机器的硬件特征码（机器码）。

### 4.3 数据模型（核心）
- `licenses`：存储授权码、到期时间、绑定机器码、包含的母鸡配额数。
- `nodes`：存储母鸡信息（IP、状态、总资源、已用资源）。
- `vms`：存储虚拟机信息（UUID、所属用户、所属节点、配置规格、状态）。

## 5. 项目管理与开发阶段：回答「怎么落地执行」

### 5.1 阶段里程碑划分
- **Milestone 1：底层核心跑通（第 1-2 周）**
  完成被控端 Go Agent 编写，实现基于 libvirt 的虚拟机基础生命周期控制（开/关/删）。
- **Milestone 2：主控与通信机制（第 3-4 周）**
  完成主控端基础框架，实现主控与被控的安全通信，跑通母鸡一键接入流程。
- **Milestone 3：商业授权系统（第 5 周）**
  完成独立授权中心的开发，集成主控端 License 校验与母鸡配额扣减逻辑。
- **Milestone 4：业务闭环与面板开发（第 6-8 周）**
  完成用户端购买流程、财务系统及管理员后台的所有 Web 界面。

### 5.2 开发规范
- 统一使用 Git 进行版本控制，实行分支管理（主分支稳定，特性分支开发）。
- 接口定义必须提供清晰的 Swagger/OpenAPI 文档。
- 后端代码必须包含单元测试，特别是授权校验与账单扣费等核心逻辑。

## 6. 测试与质量阶段：回答「做的对不对」

### 6.1 测试重点
- **环境兼容性测试**：在不同 Linux 发行版上运行被控端一键安装脚本，确保依赖（libvirt、qemu、网络组件）正确安装并启动。
- **授权绕过测试**：模拟断网、修改本地时间、伪造授权服务器响应等极端情况，验证授权系统的健壮性。
- **并发与压力测试**：模拟主控同时向多台母鸡下发数十台虚拟机创建任务，验证系统不崩溃且状态一致。
- **网络隔离测试**：验证同母鸡下不同用户的虚拟机网络互相隔离，防范 ARP 欺骗和 IP 盗用。

### 6.2 缺陷管理
- 使用 Jira 或禅道跟踪 Bug，分级处理（致命、严重、一般、轻微）。
- 核心流程（购买、交付、扣费）的 Bug 必须在上线前清零。

## 7. 上线与发布阶段：回答「怎么安全上线」

### 7.1 发布物准备
- **授权中心服务端**：部署在官方自营服务器上，确保高可用。
- **主控端安装包/Docker 镜像**：提供给客户下载，包含自动化部署脚本。
- **被控端一键安装脚本**：托管在官方 CDN 上，确保客户母鸡能快速拉取。
- **产品文档**：详尽的安装指南、使用手册、常见问题排查（FAQ）。

### 7.2 发布流程
- **内测（Alpha）**：团队内部环境部署验证。
- **公测（Beta）**：邀请部分种子客户免费试用，收集真实环境反馈。
- **正式发布（GA）**：开启商业售卖通道，上线官网与支付系统。

## 8. 运维与迭代阶段：回答「上线后怎么维护」

### 8.1 客户支持与运维
- 建立官方工单系统与客户交流群，提供技术支持服务。
- 收集客户母鸡在各种复杂网络环境（如 NAT 后、多网卡）下遇到的部署问题，持续优化一键安装脚本。

### 8.2 后续迭代规划
- **v1.1**：支持完整的快照备份与还原功能。
- **v1.2**：引入按小时计费模式，完善财务报表。
- **v2.0**：支持高级网络特性（VPC/VxLAN）与分布式存储（Ceph）接入。
- **持续优化**：不断丰富官方系统镜像库，优化授权防破解机制。
