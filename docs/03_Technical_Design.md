# 商业化 IDC 云管系统 - 04. 技术设计阶段详细说明

这部分是项目最核心的“落地图纸”，直接指导 Go 语言后端的编码。绝不含糊。

## 4.1 KVM 母鸡的一键接入架构

系统商业化成功与否，很大程度取决于小白用户能否顺畅安装被控端。

### 4.1.1 自动安装脚本（install.sh）的设计哲学
- **强行接管网络（最容易翻车的点）**：
  - KVM 虚拟机要上网，必须在物理机上建一个网桥（如 `br0`），把物理网卡（如 `eth0`）绑上去，把 IP 挪到 `br0` 上。
  - 安装脚本必须智能识别目标系统使用的是 `Netplan` (Ubuntu 20+)、`NetworkManager` (CentOS 8+) 还是传统的 `/etc/network/interfaces` (Debian 11)，并**无感修改网络配置，自动重启网络**。如果失败，物理机就会失联，客户会骂娘。
- **无依赖的二进制发布**：
  - 脚本不应在母鸡上执行 `go build`。应该从官方 CDN 下载预编译好的 `amd64` 架构可执行文件。
  - `install.sh` 仅做四件事：安装必要的系统包（qemu, libvirt），配置网桥，下载二进制文件，写入 Systemd 服务配置并 `systemctl enable --now`。

### 4.1.2 注册与认证流程（Node Token 机制）
1. 主控端后台生成一串 JWT 格式的 `Node-Token`，包含过期时间（如 1 小时内有效）。
2. 管理员复制命令：`curl .../install.sh | bash -s "NODE_TOKEN"` 到母鸡执行。
3. 母鸡安装完毕后，Agent 进程启动。它读取传入的 `NODE_TOKEN`，获取本机的公网 IP、MAC 地址、CPU 核心数、内存总量。
4. Agent 发送 HTTPS POST 请求至主控端的 `/api/node/register`，携带上述信息。
5. 主控端校验 Token 的有效性，同时**向官方授权中心发起配额校验请求**。
6. 如果主控端的母鸡总数未超已购配额，授权中心返回 HTTP 200。主控端生成一对用于日后长连接通信的 TLS 证书（或长效 Secret Key），返回给 Agent。
7. Agent 将证书/Key 存入本地 `/etc/idc-agent/config.yaml`，注册成功。

## 4.2 主控与被控的安全通信机制

这是分布式系统的基石，也是防黑客攻击的核心防线。

### 4.2.1 为什么放弃纯 HTTP？采用 gRPC + mTLS
- 如果用纯 HTTP 提供开机关机接口，极其容易被抓包伪造请求。一旦被黑客控制，全服的虚拟机都会被删除。
- **技术方案**：
  - 采用 **gRPC**。它是基于 HTTP/2 的强类型 RPC 框架，性能极高。
  - 启用 **mTLS（双向 TLS 认证）**。
  - 主控充当内部的 CA（证书颁发机构）。
  - 主控有自己的服务端证书，每个接入的母鸡 Agent 在注册时都会获得一张由主控签发的客户端证书。
  - 只有拿着这张合法证书的请求，主控才会处理；同理，母鸡 Agent 也只接收主控签发证书的连接，彻底杜绝了伪造指令。

### 4.2.2 异步任务的削峰填谷（Redis Queue）
- 创建一台 50G 磁盘的虚拟机可能需要几秒到十几秒。主控不可能一直阻塞等待。
- **流程设计**：
  1. 用户点击购买，主控数据库创建一条状态为 `Creating` 的 VM 记录。
  2. 主控将任务（包含配置规格）压入 Redis 队列。
  3. 主控内部的 Worker 取出任务，通过 gRPC 异步调用目标母鸡 Agent 的 `CreateVM()` 方法。
  4. Agent 在后台执行克隆磁盘、生成 Cloud-Init 等耗时操作。
  5. 操作完成后，Agent 通过 gRPC 回调主控的 `UpdateVMStatus()` 接口，将状态改为 `Running`。
  6. 前端面板通过 WebSocket 或轮询，向用户展示进度条（如 10%... 100%）。

## 4.3 商业防破解与授权校验体系（反白嫖）

商业软件的核心护城河。一旦被出破解版，将血本无归。

### 4.3.1 机器码（Machine ID）生成算法
- 主控端启动时，通过读取底层的硬件序列号生成唯一哈希。
- **Go 语言实现思路**：
  - Linux 下读取：`/sys/class/dmi/id/product_uuid` (主板 UUID)。
  - 读取：第一块物理网卡的 MAC 地址。
  - 读取：`/proc/cpuinfo` 的 CPU 序列号。
  - 将上述三者拼接，进行 SHA256 加密，作为这台主控服务器的“身份证”。

### 4.3.2 离线与在线混合校验策略
- **在线心跳（Heartbeat）**：
  - 主控端有一个隐藏的 Goroutine，每隔 6 小时向官方授权中心发送 HTTPS 请求。
  - 载荷包含：`License Key`、`Machine ID`、`当前管理的母鸡数量`、`当前活跃的虚拟机数量`。
  - 官方中心比对数据库，如果 `Machine ID` 变了，或者母鸡数量超过了配额，返回错误码（如 `403 Forbidden`）。
- **离线容忍与熔断机制**：
  - 如果官方授权服务器宕机，或者主控服务器网络波动，主控不会立即死机。
  - 系统允许最多连续 3 天心跳失败（离线宽限期）。
  - 若超过 3 天未成功连通授权中心，主控触发**熔断**：强制锁定所有管理员操作接口（如无法添加新母鸡、无法新建虚拟机），并在后台顶部挂出醒目的红幅：“授权服务器失联，请检查网络或续费”。但**绝不影响已有虚拟机的正常运行**，保证租户的业务底线。

### 4.3.3 代码混淆与防逆向
- Go 语言编译出的二进制文件虽然不容易直接反编译出源码，但依然可以通过工具看到明文的字符串和函数名。
- **发布前处理**：
  - 编译时加上 `-ldflags "-s -w"` 剥离符号表和调试信息。
  - 核心验证逻辑部分（如校验 License 的函数）推荐使用第三方混淆工具（如 `garble`）将变量名、函数名混淆为无意义字符，增加破解者寻找关键跳转判断（如 `if isValid == true`）的难度。
