# 商业化 IDC 云管系统 - 01. 立项与规划阶段详细说明

## 1.1 核心商业模式深度拆解

系统设计的核心必须围绕“如何卖授权”和“如何防止白嫖”。系统的计费核心不在主控软件本身，而在于“控制能力的规模”。

### 1.1.1 授权售卖组合策略
- **主控基础版授权**：
  - 售价模式：月付 / 年付 / 永久买断。
  - 包含权益：允许安装 1 个主控端，默认赠送 N 台（如 2 台）母鸡节点配额。
  - 适用场景：针对刚起步的小型 IDC 或个人玩家，降低入门门槛。
- **独立母鸡配额扩容**：
  - 售价模式：按“节点数量阶梯”一次性买断或按年付费。
  - 包含权益：主控基础版配额耗尽后，每额外添加 1 台 KVM 母鸡，必须购买 1 个节点配额。
  - 适用场景：针对规模扩大的中大型 IDC，业务越大，需要购买的配额越多，实现价值最大化。

### 1.1.2 授权绑定的唯一性与防倒卖设计
- **主控授权绑定（一对一）**：
  - 一个 License 码必须强绑定主控所在服务器的**唯一硬件特征码**（机器码：CPU 序列号 + 主板 SN + 网卡 MAC 组合哈希）。
  - 若主控服务器更换硬件或迁移，必须在授权中心自助操作解绑并扣除换机次数，防止一个 License 被多方复制使用。
- **母鸡归属验证（一对多，且排他）**：
  - 一台母鸡只能属于一个合法主控。
  - 母鸡被控端安装时，必须提供主控颁发的 `Node-Token`。
  - 母鸡与主控建立通信时，主控必须向总授权中心上报当前已接入的母鸡总数，若超过授权配额，主控强制拒绝新母鸡的接入并发送告警。

## 1.2 项目价值与竞品差异化打法

为什么要自研？因为现有市面产品（如 SolusVM、Proxmox VE、部分开源面板）存在痛点，这就是本系统的商业突破口：

- **痛点 1：PVE 安装门槛高，商业面板授权死板**。
  - **我们的打法**：极简的一键接入。IDC 拿到一台纯净版 CentOS/Ubuntu 物理机，无需手动安装任何虚拟化底座，直接跑一行 `wget -O- https://xxx/install.sh | bash`，系统自动装好 KVM、网桥并连上主控。
- **痛点 2：授权一刀切，小商家买不起，大商家觉得亏**。
  - **我们的打法**：“主控授权 + 独立配额”分离。低底薪（便宜的主控） + 高提成（卖配额赚钱）。
- **痛点 3：前端界面老旧，不符合现代审美**。
  - **我们的打法**：提供现代化、响应式的 Vue 3 面板，且允许商业客户通过支付“白标授权费”（White-label License）去除系统底部的版权标识。

## 1.3 资源投入与启动准备

开发一套能卖钱的商业系统，不是写几个脚本那么简单，必须明确资源投入：

- **核心资产：独立授权认证服务器（Auth Server）**。这是整个商业帝国的命脉，必须部署在极其稳定且具备高防 IP 的官方服务器上。所有售出的主控必须定时与该服务器心跳通信。
- **研发基座：多硬件环境测试实验室**。必须准备至少 3-4 台不同网卡型号、不同 Linux 发行版（Ubuntu 22.04、Debian 12、AlmaLinux 9）的物理服务器，用于死磕 KVM 底层和网桥创建的兼容性。
- **产出物标准**：不只是写代码，必须产出“安装手册”、“API 接口文档”、“常见问题排查手册”，因为 IDC 客户遇到问题会疯狂提工单，完善的文档能节省 80% 的售后成本。
